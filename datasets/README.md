# Датасеты

Для каждого датасета выделена директория `datasets/<name>/`. В ней хранятся конфиг и скрипты подготовки датасета, а в поддиректории `data/` — исходные и преобразованные данные.

## Структура

На примере датасета SIFT1M структура директорий ниже:
```text
datasets/
├── README.md
└── sift1m/
    ├── dataset.json
    ├── download.py
    ├── convert.py
    └── data/
        ├── base.bin
        ├── queries.bin
        └── raw/
            ├── sift.tar.gz
            ├── sift_base.fvecs
            └── sift_query.fvecs
```

- `dataset.json` задаёт метрику, размерность и количество векторов в базе для построения и запросной части.
- `download.py` скачивает и извлекает исходные файлы.
- `convert.py` преобразует исходные файлы в общий формат бенчмарка.
- `data/base.bin` содержит векторы базы для построения индекса.
- `data/queries.bin` содержит запросные векторы.

## dataset.json
Все поля являются обязательными, сам `dataset.json` должен генерироваться внутри `convert.py`. Пример `dataset.json` ниже:
```json
{
  "metric": "l2",
  "dim": 128,
  "base_count": 1000000,
  "query_count": 10000
}
```

## download.py
Этот скрипт должен скачивать исходный датасет в `datasets/<name>/data/raw`

## convert.py
В репозитории поддержан единый формат файла для построения базы произвольного бекенда, из себя он представляет матрицу `float32`, где все векторы записаны в `little-endian`, имеют одинаковую размерность и лежат плотно подряд.

Если датасет уже содержит запросы, то они хранятся так же, как и данные для построения базы. Иначе `convert.py` должен будет засемплировать запросы из исходных данных.

`convert.py` гарантирует, что в датасете все значения будут удовлетворять `std::isfinite(value)`.

Также после завершения `convert.py` должен удалить исходные данные.
